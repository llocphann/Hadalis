# Hadalis Automation control

The Abyss Settings **Automation** page uses `scripts/hadalis-automation-control.py` as a narrow JSON interface. It stores profile settings at `$XDG_CONFIG_HOME/hadalis/automation.json` and bounded runtime state/history at `$XDG_STATE_HOME/hadalis-automation/manager.json`. The shell settings JSON is not rewritten by the automation daemon, so profile edits cannot overwrite unrelated shell preferences.

The installed `hadalis-chat-bridge.service` runs `python3 -m automation.manager.daemon`. It and the legacy bridge share `chat-bridge.lock`. One profile owns the ChatGPT transport at a time. Other enabled profiles wait by due time and stable list order. A paused owner retains its chat; stopping it releases the queue after any in-flight response completes. Interval runs release their owner after a turn and schedule a later fresh chat. The manager keeps the original strict-lossless prompt and directive semantics for the built-in profile. New profiles use a general continuation template; edited prompts are wrapped with fixed GitHub, current-dev, ChatGPT-only and no-Work-mode rules.

Before every submission the driver requires an empty composer and no active Stop control. It also records the count of completed response controls. The manager persists that baseline **before** submitting and accepts only a later completed assistant response with one loop marker. If submission outcome is uncertain, it polls the same baseline and never resends the prompt automatically. Repeated poll errors use bounded backoff and pause after the configured limit. A connector-blocked directive pauses the profile distinctly from a transport error.

The bridge records only measurable elapsed time, completed turns, sent prompts, failures, job IDs and scheduling times. ChatGPT conversation IDs are not exposed reliably by the current desktop transport. Archive, delete, old-chat cleanup and composer recovery preferences are persisted and clearly marked pending in Settings; they do not act on ChatGPT until a deterministic semantic API exists. No currently active or uncertain chat is cleaned.

Install the service units from a repository checkout with `python3 scripts/install-hadalis-automation.py`. `--reset-session-state` clears the old and managed bridge session state under the shared transport lock while retaining profile configuration. `--enable-now` starts all three user services. `python3 scripts/hadalis-automation-control.py status` prints the same live status snapshot used by Settings.
