# Cloud Storage / MEGAcmd — source-level audit and implementation blockers (research round 2)

**Status: evidence-backed technical research only. No Cloud Storage QML/Rust/runtime changes and no MEGA account commands executed.**  
Date: 2026-09-30, Vietnam time. Hadalis `dev` baseline: `0bd28b0009c1e0691a955922b2da2b3c8cbc1e19`. Official MEGAcmd source pinned at [`6505327a5`](https://github.com/meganz/MEGAcmd/tree/6505327a5a7a0e94f26f611f83b024aeeb63582c); official SDK source examined at [`74326bb0`](https://github.com/meganz/sdk/tree/74326bb0aa09b13f0a1ec8eab9611e4c0de98cc6). Read alongside [the full 76-command / ten-section design](CLOUD_STORAGE_MEGACMD_FULL_DESIGN.md), which inventories functionality and UX; this audit records **confirmed source-level constraints, corrections, decisions and concrete implementation gates**.

## Executive engineering findings

The full QML feature **information architecture** is designed, but a safe, general-purpose file manager is **not implementation-ready** merely because Rust runs `mega-*` subprocesses and emits JSON. Upstream MEGAcmd's scriptable client reconstructs its argv as a text command, and even its separated column output does **not** escape cell contents. Vendor command parsing, not JSON speed, is the dominant correctness blocker for arbitrary user-controlled filenames. A different validated/vendor-supported node API is necessary if unrestricted GUI file mutations are a hard product requirement. A staged Rust CLI adapter remains suitable for *validated* sync, transfers and backups; gate the file manager to capabilities actually proven safe.

No password/MFA/session/public-link key through QML→Rust argv/JSON. Merely adding an SDK instance does not make it the same login or sync owner as MEGAcmd. |
| [Upstream open issue #1134](https://github.com/meganz/MEGAcmd/issues/1134) (reported with 2.1.1) | A real report shows a sync ID starting with `-` can be interpreted as options when passed to `mega-sync -d`. | Version-probe a leading-dash synthetic sync ID. | [Upstream open issue #1135](https://github.com/meganz/MEGAcmd/issues/1135) (reported with 2.5.2.1) | A reporter describes indefinitely hanging CLI commands when a server becomes unresponsive. | All vendor calls need absolute wall-clock and output-size bounds, meaningful `SERVER_UNRESPONSIVE`/degraded UI, backoff and manual diagnostics. Killing the client is not a safe assertion that a queued server-side write was canceled; **never auto-kill someone else's server**. Not proof 2.6.0 is affected. |

### Release-specific corrections

Official [2.6.0 packaging changelog](https://github.com/meganz/MEGAcmd/blob/6505327a5a7a0e94f26f611f83b024aeeb63582c/build/megacmd/debian.changelog#L1-L22) is dated **19 August 2026**. It records always-HTTPS transfers: `mega-https on` is a no-op and `off` is rejected; **do not expose an HTTP/HTTPS toggle** on 2.6.0. It documents WebDAV caching/reclaim controls, more efficient large-folder path lookup and Linux/macOS environment proxy fallback, so treat proxy and cache controls as version-gated features rather than universal hardcoded behavior. `mega-update` is **not a Linux software updater** according to official command docs; link to the owner's package manager instead. The presence of a public changelog does **not** verify the owner's installed version.

## 1. Backend access options: choose by guaranteed behavior, not language fashion

| Option | Strengths | Limitations and go/no-go |
| --- | --- | --- |
| **A. Rust → official `mega-*` clients → MEGAcmd server** | Reuses currently supported vendor daemon/session/sync state; easy optional dependency; Hadalis already ships a production Rust workspace. | Recommended for *tested* status, sync IDs, transfers, backup, quota and narrow paths. **No blanket "all filenames / 100% safe Drive" claim** because the vendor reparses arguments and emits unescaped tables. |
| **B. Official MEGA C++ SDK via a separate rigorously encapsulated helper** | Provides programmatic node objects/handles and a documented `restoreVersion` API not found in reviewed CLI set; may solve arbitrary-node listing/mutation only if validated. | Separate SDK instance needs account authentication/session state, resource costs, concurrent external-client policies, C++/Rust FFI boundary, build/link/license review and dangerous cross-client sync interactions. Never import vendor private MEGAcmd session files or silently initialize a second sync engine. **Research track only**, not authorized for runtime. |
| **C. Speak directly to MEGAcmd's internal Unix socket** | Can theoretically avoid per-client fork and human-table formatting; source reveals socket/framing paths. | Protocol, server auto-start, event subscription, confirmations and serialization are internal implementation—not an established stable public API. **Do not implement** unless vendor publishes/commits to a supported protocol and compatibility policy. |
| **D. Rewrite sync/scheduler in Rust** | No legitimate first-phase upside. | Duplicates vendor sync/conflict/retention machinery and risks divergence. **Explicitly out of scope.** |

**Current architecture decision:** keep Rust + JSON as the **Hadalis boundary**, official MEGAcmd as **the sole sync and backup engine**. Implement full ten-section UI *design*, but capability-gate actions that cannot be represented safely through installed CLI. If the product must provide reliable unrestricted Drive browsing/restore, require a separate explicit SDK feasibility and threat-model decision before I2/I3. Do not conflate "76 documented commands mapped" with "76 safe programmable integrations."

## 2. QML UX corrections and explicit states

1. **Connection consent first.** An installed binary does not imply an active server, authenticated session or permission to boot MEGAcmd. The Overview shows `Not installed` / `Installed · Not connected` / `Connecting` / `Connected · Signed out` / `Running` / `Degraded` / `Offline` / `Stale`. `Connect` explains it may start the server and that closing Settings will **not** stop sync/backup.
2. **Account transition guard.** Every snapshot is stamped with an opaque account/session fingerprint (derived only from nonsecret vendor identity; do not persist session IDs). Invalidate selected remote handles, transfer tags, queued mutations, filters and view caches on logout/external account switch.
3. **Drive must visibly support partial capability.** Directory listing is view-only if filenames/handles cannot be unambiguously decoded. Disable only unsupported write controls, not the whole page. Don't infer backend remote pagination from locally displaying 100 rows; cap CLI output and show `Result truncated · refine search` rather than silently hiding items. No HTML rendering of `mega-cat` or metadata.
4. **Sync has three badges.** `RUN_STATE` (Pending/Loading/Running/Suspended/Disabled), `STATUS` (NONE/Synced/Pending/Syncing/Processing), and `ERROR/issue count` are orthogonal vendor dimensions. Show `Sync Issues` with IDs and delayed-snapshot caveats; users should never see "Everything synced" from one valid `mega-sync` command exit.
5. **Backup is not Sync.** Display `ONGOING`, `INCOMPLETE`, `ABORTED`, `MISCARRIED`, `SKIPPED`, next scheduled run and vendor-provided history. Creation warns *first backup may run immediately*. Display UTC-origin vendor schedule, local equivalent and retention consequences without claiming arbitrary timezone scheduler support.
6. **Transfers race with actions.** Pause/cancel by verified current TAG; return `not found / already completed` when appropriate. Never equate process timeout with cancellation of a queued vendor transfer. Optionally expose small in-app 15–30s diagnostics history without retaining raw paths/tokens.
7. **Sharing, contacts, public links.** Public links (including link fragments), session handles, auth-key and password-bearing exports are secrets. Treat view/copy as user-invoked; exclude from notification and exported logs. Provide account-plan gating on export expiry/password and contact verification guidance, but block an option requiring secrets via argv.
8. **Mounts/Local Access.** Keep FUSE beta badge, read-only default and disk-cache warning. WebDAV localhost-only until separately reviewed; WebDAV supports streaming, FUSE **does not**. Never offer "enable public FTP/WebDAV" without explicit network/TLS/firewall threat assessment.
9. **Security center.** Native in-QML login is not ready. Launch an official interactive shell for owner sign-in. Make `logout` irreversible effects explicit: a normal vendor logout can remove local session cache/config; `--keep-session` has different semantics and must not be mislabeled "secure sign out".
10. **Diagnostics and recovery.** Last action, error category, redacted vendor code, elapsed time, last successful refresh and action reconciliation. Export a **minimal structured JSON projection** after an opt-in preview/anonymization step; no `mega-session` or full vendor logs.

### Error + state contract refinement

The Rust JSON contract uses: `protocol_version`, `request_id`, `backend_kind`, `backend_version` (when actually observed), `account_epoch`, `observed_at`, `ok`, `stale`, `operation`, `data`, `error{code,stage,retriable,diagnostic_id,redacted_message}`. QML must distinguish `DEPENDENCY_MISSING`, `CONSENT_REQUIRED`, `SERVER_NOT_RUNNING`, `SERVER_UNRESPONSIVE`, `LOGIN_REQUIRED`, `UNSUPPORTED_VENDOR_VERSION`, `AMBIGUOUS_VENDOR_OUTPUT`, `UNSAFE_PATH`, `SYNC_ID_UNREPRESENTABLE`, `COMMAND_TIMED_OUT`, `ACTION_OUTCOME_UNKNOWN` and confirmed vendor business errors.

**Four-stage action lifecycle:** (1) validate parameters and identify the specific owner/session; (2) show human confirmation for destructive or sharing/network-exposed actions; (3) dispatch once under a per-user action lock, returning `pending` or `unknown` on transport timeout; (4) perform a fresh authoritative vendor query, return `confirmed` only if requested postconditions hold. Do **not** automatically retry writes after ambiguous timeouts, and do not equate local process completion with vendor-level effect. If external MEGAcmd clients race with Hadalis, show observed final state rather than attributing ownership falsely.

## 3. Adversarial fixture suite: mandatory before any mutating Drive/sync code

Fixtures must use a disposable account and directory tree, not the maintainer's actual home/MEGA storage. Do **not** hand these real-account tests autonomously to the deterministic Local Bot.

| Fixture class | Concrete cases | Pass/fail rule |
| --- | --- | --- |
| CLI roundtrip | Ordinary ASCII, Vietnamese Unicode, spaces, tabs, embedded double/single quotes, backslash, CR/LF, leading `-`, `--`, semicolon, wildcard `*`/`?`, regex metacharacters, trailing spaces, 255-byte filename, duplicate cloud names, symlinks | Every target must be correctly and **uniquely** identified; ambiguous case = read-only/unavailable, never wrong-node mutation. |
| Tabular parser | `--col-separator` appears inside local/cloud paths, embedded newline, long path + `--path-display-size`, column reordering, null/empty ERROR, truncated stdout, non-UTF8 surrogate/error bytes | Parser either returns an exact typed result or explicit `AMBIGUOUS_VENDOR_OUTPUT`; no silent skipped rows or false "0 issues". |
| IDs/option tokenizer | Normal sync ID, ID beginning `-`, `-p`/`-d`/ `--` synthetic forms, transfer tag removed externally | Any ID unsupported by installed CLI disables that specific mutation and reports a repair path; **never** reinterpret it as flags. |
| Server lifecycle | Binary missing, binary exists/server stopped, previous server running, server crashed/hung, server restarting/updating, different XDG_RUNTIME_DIR/HOME, terminal session from another user | No hidden server start before Connect; known-running server never killed automatically; bounded waits and stale snapshots. |
| Authentication | Signed out, external login, wrong password/MFA, logout `--keep-session`, external logout, account change midway through action | QML never receives password/session token; stale caches/actions revoked; no claim that logging out preserves jobs unless verified. |
| Files & versions | Remote folder with duplicate names, nested paths, Rubbish root (`//bin`) view, file versions list, SDK restore only on isolated SDK account if separately approved | No unconditional "Restore" for CLI where no established command semantics; irreversible delete-versions has dedicated confirmation or is disabled. |
| Sync + competing clients | New source folder, nested overlap, symlink/realpath alias, bind mount, same folder watched by MEGA Desktop, suspend/resume, changed file during create | No double ownership or unexpected first sync; prompt explicitly for bidirectional deletion/conflict implications; test only disposable content. |
| Backup | First backup immediately, six-field UTC cron/daylight saving display, retention limit, overdue while server down, incomplete/aborted/miscarried/skipped | Vendor states preserved; no silent snapshot deletion; no extra Hadalis scheduler. |
| FUSE/WebDAV | FUSE unmounted/unsupported, cache disk full, delayed upload, logout, WebDAV localhost binding, TLS invalid, port conflict | Guard capability, warn before data loss/network exposure; no false "fully uploaded" claim. |
| UI + build | Standalone/rail/focus; Abyss/Waffle; saved category arrangement; hidden-loader lifecycle; source/Arch/Nix install; preview diagnostics | Same canonical page everywhere, no eager provider polling, packaged binary present or feature gracefully absent. |

For the executable baseline, record installed versions, command help, distro, vendor stdout/stderr sample fixtures **after removing all secrets and real personal filenames**, command/response elapsed time and exit semantics. CI parser tests must replay those **recorded sanitized** fixtures plus generated malformed samples; do not call live MEGA automatically.

## 4. Rust/Quickshell lifecycle and packaging: exact Hadalis file audit

Hadalis **already runs Rust as a production default** in [`native/README.md`](../native/README.md) and [`scripts/native-dispatch`](../scripts/native-dispatch). Its workspace already uses [`serde`, `serde_json`, Rust 2024 / 1.95 and thin release LTO](../native/Cargo.toml). Reuse the existing production architecture; the initial feasibility document's Python bridge is **historical**. Rust being native should be evaluated as a low-overhead adapter, not a second permanently resident event loop without data.

A new binary requires more than one workspace member: [`native/scripts/install-runtime.sh`](../native/scripts/install-runtime.sh) hardcodes the current four binaries; [`Makefile` install and test-prefix-install](../Makefile) assumes those four; [Arch packaging](../distro/arch/inir-shell/PKGBUILD) and its Git variant, plus [`nix/package.nix`](../nix/package.nix), each install explicit binary lists. The canonical runtime payload list does **not** include the `native/` source tree; packaged compiled binaries go under `native/bin/`. Therefore, authorized implementation must update build/install/packaging **and tests atomically**; otherwise a QML page may work from a checkout yet silently fail after distribution.

For any future status service: `SettingsPageRegistryData.qml` presently ends at index 35 and `SettingsPageRegistry.qml::isPageApplicable` hides appended non-Abyss/Waffle pages by its `index < 32` guard. Append stable `cloud-storage` key; explicitly permit that index across panel families and update default grouping, search index and `SettingsNavigation.js` persisted custom-arrangement migration. Share the same `ContentPage` for standalone `settings.qml`, `SettingsOverlay.qml` and `SettingsFocus.qml`; keep subscription demand tied to actual current page/section visibility, not only `Component.onCompleted` (page cache can keep loaders resident while hidden).

**Performance measurement contract, not invented gains:** measure separate `QML button → Rust CLI startup`, `Rust client spawn`, `MEGAcmd server IPC`, `vendor/network response`, `Rust normalization`, and `QML parse/render`. Compare an equivalent Python **baseline only if one exists** and control warm/cold cache, login state, item count and power mode. Use threshold from current installed hardware. Optimize number of vendor calls and rendering before claiming any percentage from Rust itself. Zero *Hadalis-induced* cloud CPU/wakeups while feature unused is the target; the vendor's independently running daemon may still consume resources by user choice.

## 5. Concrete decision gates, in recommended dependency order

- **G0 — Product:** Confirm whether "manage MegaSync" means MEGAcmd-owned account/jobs only or control of an already-running MEGA Desktop GUI. No supported Desktop control API was proven by this source audit.
- **G1 — Installed capability:** Obtain installed version and `--help` after explicit connection consent, plus real sanitized output for each first-phase operation. The upstream source's 2.6.0 command inventory is not a substitute.
- **G2 — Parser and filenames:** Demonstrate exact target identity across adversarial output and argv roundtrip; otherwise ship only narrow, fail-closed CLI operations. If unrestricted Drive needed, separately authorize official SDK research.
- **G3 — Credentials and logging:** Use vendor interactive shell now; assess PTY/stdin only in an isolated future test. Never pass secret-bearing vendor flags through Rust argv, stdout logs or QML JSON. Validate vendor log environment overrides.
- **G4 — Data safety:** Verify `--`/leading-dash IDs on installed MEGAcmd, conflicts, double-sync path prevention, Rubbish/restore claims, permanent version deletion and backup retention with disposable data.
- **G5 — Lifecycle:** Prove zero unconsented server start, bounded server-hang behavior and no interference with externally started vendor process.
- **G6 — Deliverability:** Plan four-binary production inventory expansion in Cargo + install script + Makefile + Arch + Nix, and cross-family QML route/visibility tests.
- **G7 — Performance:** Benchmark Rust command adapter + MEGAcmd external calls end to end before asserting CPU/RAM/latency improvements; choose event-driven only if an official supported vendor API and benchmarks justify it.
- **G8 — Approval:** No source code edits, credentials, destructive test or live MEGA commands until the maintainer expressly authorizes implementation and identifies a disposable test environment.

**Net result of round 2:** A safe Rust front-end for selected MEGAcmd workflows is architecturally feasible and fits Hadalis; general all-filename file-manager correctness, in-page auth and restore-version functionality are **evidence-gated** rather than "complete". No runtime behavior or live account was verified by this desk research.
